# 架构与二次开发

## 边界

本项目是一款不依赖后端的单机益智游戏。无需构建框架、网络 API、账号、数据库、外部 CDN 或付费资源。生产成品有两种表示：普通静态目录 `dist/`，以及所有资源内嵌的 `STRATA-Offline.html`。两种表示来源于同一份游戏代码，不维护两套玩法。

技术栈是普通 ES Modules、Three.js r140、DOM/CSS、Web Audio、localStorage，以及可选的 C/WASM CPU 光栅内核。固定较旧的 Three.js 是当前离线开发环境中可实际取得并运行的依赖，不是“已使用最新版”的宣传。升级应独立提交，尤其检查材质色彩管理、ShaderChunk、自定义 uniforms、剖切、阴影和导出图片。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/engine.js` | 坐标与规则、碰撞、回退/撤销/重做、重力和泵、单回路 BFS、流动状态、计分、存档路线恢复验证 |
| `src/levels.js` | 8 个专门编排关卡、固定种子章节、每日种子、先解后障碍生成器 |
| `src/scene.js` | 机柜、设备和管路几何，镜头、射线点选、剖层、GPU 注入着色器、资源释放 |
| `src/software.js` | 同一 Three 场景的 CPU 投影、几何缓存、材质适配、像素输出 |
| `render/raster.c` | 自写三角形光栅内核；深度、插值法线、近似金属着色、透明混合和阴影贴图 |
| `src/kernel.js` / `render/raster.wasm` | 同一内核的内嵌 JS 数据与原始编译产物；测试会验证字节一致 |
| `src/legacy.js` | WASM 初始化失败时的基础 Canvas 降级渲染器 |
| `src/main.js` | DOM 界面、输入事件、应用状态、弹窗、JSON 文件导入导出、自动存档和动画调度 |
| `src/storage.js` | 存储异常隔离、版本化 profile、记录、导出/导入、数据清洗 |
| `src/audio.js` | 用户手势触发的合成提示音，关闭/音量控制 |
| `src/style.css` | 响应式界面、触屏布局、状态和可访问性样式 |

游戏状态不从渲染物体反推。引擎持有唯一规则状态，三维模型与楼层板是它的两个视图。这样降低了“画面接上了但规则没接上”和“俯视图与空间图不一致”的风险。

## 网格、管路与工程规则

坐标为 `[x, y, z]`，y 向上，界面显示楼层 `L(y+1)`。x、z 范围是 `0..size-1`，y 是 `0..height-1`。UI 和手册的“格”是离散游戏单位，没有换算成米或真实管径。

每条管路是从入口开始的有序节点数组。合法新增节点必须六方向相邻、在界内，且不占设备、其他液体端口或其他液体路线。不同高度可以有相同 x/z。点击自己的旧节点会截断数组，故不会制造支路、环形分叉或重复节点。

每条上升边在 gravity 模式计 1 台泵；计算额度时遍历所有已铺路线，删除或撤销后自动得到正确剩余额度。没有伪造压力、流速、压降数据，也没有宣称真实 CFD。

渲染中一格映射为 0.94 个场景单位。管路拐角使用二次曲线圆角，再生成 TubeGeometry。接头位于边中点，上升边在重力关中替换为金色泵。模型颜色和端口字母共用 `COLORS` / circuits 数据。

## 状态机

`editing → running → won`。所有液体接通才允许进入 running。运行期间禁止布管、撤销和提示；可以停止运行回到 editing。tick 只在页面可见、未暂停、无模态弹窗时推进。通关后保存成绩，再打开报告。重开会创建新状态，不修改历史最佳记录。

导出存档没有保存 GPU 对象、音频对象或 DOM。恢复时从合法起点依次重放保存路线，用同一套 `step` 规则验证；不相信导入的 won 标记，不允许坏路线绕过碰撞。撤销历史不会跨刷新恢复。运行中刷新会恢复到布管状态，而不是继续一段失去时序上下文的动画。

## 生成器的保证与非保证

生成器通过固定种子伪随机过程，先创建若干互不重叠、含高度变化的自避参考路线，再在未被参考路线占用的格点放障碍。上升边总数决定 gravity 参考解所需泵额度。高密度随机尝试失败时，使用确定性的独立通道回退方案，避免无解或无限等待。

验证器逐一检查边界、端点、相邻、重复、障碍重叠和泵预算。它保证附带路线可解，但不保证唯一解、最短解或人类感受到的难度。固定章节标签不是用户测试得到的难度等级。

提示优先使用仍合法的参考路线前缀；偏离参考解时，对当前回路使用含剩余上升预算的 BFS。它不是多回路全局搜索，可能需要玩家撤回其他路线。界面明确说明这个限制。

## 存储和信任边界

版本号 `profile.version = 1`，localStorage key 是 `strata.flow.v1`。导入进度限制 400 KB，关卡限制 200 KB；字段范围和路径会再次校验。用户可控制的文字在 DOM 中使用 textContent 或 HTML 转义。

这是离线游戏，不提供抗作弊保证。客户端星数和本地日期不能直接作为真实奖品、比赛排名、支付权益的可信依据；相关场景需要另行设计服务端校验。

读取/写入存储异常会显示提示，不阻断规则引擎；本地存储不可用时建议导出 JSON。不同浏览器/来源地址的存储空间不共用。正式上线前应增加真实浏览器的迁移、损坏恢复与版本升级测试。

## 渲染和资源管理

正常设备创建 WebGL2 或 WebGL 上下文，再交给 Three.js。渲染器配置透明画布、正交镜头、阴影、色调映射和局部剖切。内管使用自定义着色器控制注入进度和流光；外管为透明材质。`preserveDrawingBuffer` 用于截图，会增加一定成本，应在目标设备性能验收时评估。

初始化无法创建 WebGL 上下文时，使用 Canvas2D CPU 软件渲染。它遍历相同的 Three.js Mesh、InstancedMesh、Sprite 和线段，投影到屏幕，先深度测试不透明三角形，再合成透明部分。液体注入通过同一组 uniforms 驱动的软件分支呈现。它不执行 GLSL，也不验证 GPU 材质实现。WASM 模式使用 1024×1024 的真实深度阴影图，并在阴影阶段尊重楼层剖切；基础 JS 降级分支仍使用较简化的阴影。CPU 分支不实现 PMREM、真实透射或 WebGL 后处理。

场景加载/重建时释放非共享几何、材质和纹理。共享几何、程序化材质及微表面纹理由 scene 级缓存持有，到 scene.dispose 再释放；局部资源以 Set 去重。静态物体按材质和阴影标志合批，但保留楼层、端口和旋转零件边界，避免合批破坏剖切或运动。CPU 纹理采样缓存使用 WeakMap，避免持有已经卸载的图像。当前测试没有进行目标 GPU 的长时内存增长验收。

## 扩展顺序建议

先在目标设备完成 `RELEASE_CHECKLIST.md` 中的渲染、交互和版本更新验收，再改引擎版本或接入平台 SDK。增加一种玩法应先扩展纯规则与测试，再修改表现层。账号、支付、云存档不应直接写进场景渲染模块。增加关卡使用 `examples/cross-layer.json` 的结构，提供 reference solution 并用 `validateLevel` 校验。

## ATELIER 02 的相机与 CPU 绘制调度

视角按钮设置角度、缩放、目标中心三个目标值，以指数阻尼过渡。角度按最短转向归一化。减少动态效果时直接到达目标。主页 GPU 微动缓慢返回默认构图，避免手动旋转后突然跳回。展示环视需主动开启，角速度缓慢变化，俯仰采用阻尼。

CPU 在静止时缓存画面，不会把空闲状态的 0 FPS 当作性能故障。拖拽、惯性、试运行或主动环视时，按约 720,000 像素预算绘制；低功耗约 440,000 像素。预算仍受最高采样和缓冲尺寸限制。运动结束后重新绘制清晰静帧；截图时也先重绘高精度帧。

渲染和规则时间分离：规则 tick 使用真实帧间隔，上限 1 秒用于过滤巨大卡顿；页面隐藏会暂停并重置时间基准。动画惯性使用更小的 dt 上限，不改变液体连接、泵计算和通关逻辑。

`npm run build:renderer` 使用 clang 生成 WASM 及 base64 内嵌模块。普通 `npm run build` 只使用已提交产物，不下载编译器，不依赖 npm 包。
